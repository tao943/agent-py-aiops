# PR #20 CI Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore every selected PR #20 CI check without weakening production diagnostic safety, Pyright strictness, or offline/Live test boundaries.

**Architecture:** Keep the full SQLAlchemy incident repository unchanged, but type each consumer against a narrow capability protocol. Preserve the production rule that a diagnostic job may dispatch recovery only after persisted success; make the integration fake honor that contract. Use platform-neutral path classification and the existing `live_docker` marker for environment-dependent tests.

**Tech Stack:** Python 3.13+, pytest, Pyright strict, Ruff, FastAPI, PostgreSQL, GitHub Actions.

## Global Constraints

- Do not read, print, or commit `config/user.project.json` secrets.
- Do not disable Pyright strict checks or lower test assertions.
- Do not unconditionally skip a test; Docker-dependent coverage must use the existing `live_docker` suite.
- Do not relax the persisted `succeeded` guard before automatic recovery dispatch.
- Add no dependency; reuse assessment is `reference only + localized custom fix` based on official CPython pathlib, pytest marker, and Pyright Protocol patterns.
